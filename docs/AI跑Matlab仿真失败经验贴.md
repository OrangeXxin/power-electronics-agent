# 小蓝鲸 VS Matlab：一场没跑完的仿真

## 起因

前天晚上，DeepSeek Harness 出来了，网上测评反响不错。8.17 之后 API 要涨价，我账上还剩一些余额，就想拿它搭一条自动跑仿真的流水线。

没成。余额花了，时间也花了。不写下来，这些东西就白扔了。写出来，往后有这个念头的人，能少走几步冤枉路。

## 巨人的肩膀

网上已经有人做过类似的事，我查了一圈，找到几个能参考的项目：

1. **MATLAB MCP Server**：官方连接器，打通 Codex 与 MATLAB，支持运行脚本、自动排错和单元测试
2. **Simulink Agentic Toolkit**：自动搭建仿真模型，可增删模块、搭建 PID 控制工程，能分析曲线迭代参数
3. **MATLAB Agentic Toolkit**：规范工程工作流，指导 AI 调用工具箱、写测试脚本、生成报告
4. **Agent Skills Playground**：官方实验演示项目，含嵌入式、系统工程和三维仿真可视化案例
5. **Simulink Skills**：深度调试工具，定位编译慢、代数环等问题，支持断点监控和性能优化

我把这些下载下来喂给 AI。它的思考链里，因为这些参考文档，少踩了几个坑。

## 被框住的头脑

示例也框住了 AI 的头脑。我用的 Matlab 是 **2025B**，网上资料大多是旧版本，思考链拉得很长，弯弯绕绕。逐条说：

- 电力电子库改名了：旧版叫 `elec_lib`，新版改为 `ee_lib`。有了这个库，AI 就可以调用真实物理模型。找这个库名字，废了老大力气。

- 库里的目录也换了排法。旧资料上写 `Electrical Sources`，新版叫 `Sources`；旧资料写 `Passive Devices`，新版叫 `Passive`。有几个目录名夹着换行符，`Semiconductors &\nConverters`，中间断成两行。在命令行里写这个路径，`\n` 让 MATLAB 当成转义符，路径就断了。得用 `sprintf` 把它拼出来，才认。AI 在这一步上反复栽跟头，写进去的字符串不是它以为的那个字符串。

- `ee_lib` 这个库，头一回加载花了**四十秒**，在编译物理网络。文档里没提这一手，AI 也没料到，头一次跑以为卡死了。让子弹飞一会儿，四十秒后，库加载完了。

- 授权文件出过岔子。装完 R2025b 头一天，MATLAB 起不来，报错 `-8.2`，license 无效。AI 花了十几轮查这个错，翻 license 文件，比对主机名，查 MathWorks 的错误码文档。结论是：license 是 2023 年 10 月签发的，**祖传货**，R2025b 不认。这一类问题 AI 改不了，得人去激活。我手动激活了一回，就好了。AI 在这件事上耗的轮次，够它搭半个模型。机器再聪明，授权这道门它绕不过去。

## 物理端口的死结

最费劲的一段在这里。

Simscape 的物理器件，二极管、MOSFET、电感，端口不是信号端口，是物理连接端口。程序里用 `add_line` 连，它挑方向。`RConn` 连 `LConn`，报错；`RConn` 连 `RConn`，通了。AI 试了好些组合，摸出这个规律，换个器件，又对不上。

后来找到 `simscape.addConnection` 这个函数，专门连物理端口。可它的参数要端口名，不是 `LConn1`、`RConn1` 这种编号，是 `p`、`n`、`D`、`S`、`G`、`V`、`I` 这种符号。这些符号 `get_param` 取不出来，返回空字符串，因为它们藏在 mask 里。

AI 一个器件一个器件地试。电压源的端口叫 `p` 和 `n`。二极管也是 `p` 和 `n`。MOSFET 是 `D`、`S`、`G`，**大写**，小写 `d` 不认。电流传感器有 `p`、`n`，再加一个信号输出叫 `I`。电压传感器的信号输出叫 `V`。地线叫 `V`。PS-Simulink 转换器的输入叫 `input`，输出叫 `output`。

这些名字，文档里不集中写。AI 用试错法一个个抠出来，抠到第四十多轮，物理连线才全通。十九根物理线，二十五根信号线，**四十四根全亮绿**。

## 参数名各说各的

器件的参数名也对不上版本。

| 器件 | 旧版 / 文档写的 | 新版实际的 |
| --- | --- | --- |
| `Integrator` 限幅 | `LowerLimit` | `LowerSaturationLimit` |
| `Repeating Sequence` | `TimeValues` | `rep_seq_t` |
| Simscape 电容 | — | `c`（值）、`vc`（初始电压） |
| Simscape 电感 | — | `l`（值）、`i_L`（初始电流） |
| Simscape 电压源 | `Amplitude` | `ac_voltage`、`ac_frequency` |
| 求解器 `LocalSolverChoice` | `"Backward Euler"` | `NE_BACKWARD_EULER_ADVANCER` |

这些名字没有规律。AI 查一回，错一回，改一回。人类的本质是复读机，AI 也没能免俗。每改一回，跑一次 MATLAB，等它启动，等它编译，等它报错，再读错误，再猜。一个参数名耗掉三四轮，不稀奇。

## 网络的门朝哪开

shell 访问不了 GitHub。`git clone` 不通，`curl` 也不通。AI 在命令行里试了好几回，都挡回来了。

后来它换了个路子，让 MATLAB 进程去访问网络。MATLAB 的 `webread` 能读 mathworks.com，也能读 github.com。官方的 Agentic Toolkit，那个 `.mltbx` 安装包，就是让 MATLAB 自己下载、自己装的。`setupAgenticToolkit` 一条命令，MCP server、三十个 skills、十个工具，全装上了。

> shell 出不去的门，MATLAB 出得去。这事事先没想到。

## 真官方和假官方

网上有个仓库叫 `simulink/skills`，我起初以为是官方的。AI 查了一圈才弄清楚，那是社区里一位叫"Guy on Simulink"的博主攒的，附在官方工具箱之上，不是 MathWorks 的产品。真正的官方货在 `matlab/simulink-agentic-toolkit` 和 `matlab/matlab-agentic-toolkit`，配一个 Go 写的 MCP server。

AI 最初照着社区仓库的思路走，绕了路。参考文档和实际工具，分清楚要花功夫。网上的资料，挂着 official 名头的，未必是 official。

## 过了的和没过的

先说过了的。

平均模型跑通了。**PF 0.976**，输出电压 **399.99 伏**，功率 **497 瓦**。输入电流跟着电压波形走，功率因数校正的效果出来了。这个模型是用数学模块搭的，积分器算电感电流，增益算占空比，看不到电感、电容、二极管、MOSFET 这些器件。它的好处是数值稳，好调参。坏处是离实物远。纸上得来终觉浅，照着它做不出电路板。

再说没过的。

物理模型是用 Simscape Electrical 的真实器件搭的，二极管桥、升压电感、MOSFET 开关、续流二极管、输出电容、负载电阻，看得见摸得着。连线连了四十四根，全通。一跑仿真，报错：**静态方程和代数方程消不掉**。这是理想开关模型的通病，求解器解不动。

AI 试了局部求解器，参数填对，还是不行。到最后这一步，它停住了。

## 打开看

AI 报告四十四根线全亮绿，连上了。我打开 Simulink 界面一看，模块叠在一起，挤成一堆。线从程序上讲一根没少，全连上了，可模块的位置没人管。`add_block` 加进去的时候坐标没排，全压在一处。

平均模型也这样。PF 0.976 是真的，399.99 伏也是真的，可那个模型打开来，积分器压在增益上面，示波器盖在求和点上，线从一堆模块底下钻出来，分不清谁连谁。

AI 能把线连对，不会排版。它不知道一个电路图该怎么摆，人看了才舒服。

> 程序返回成功，人打开一看，两回事。

## 收场

物理模型的连线全通了，仿真没收敛。中间差的一步，是 Simscape 求解器的配置和参数整定。这一步要经验，AI 没有这个经验。

事后想，四十四根线 AI 连了四十多轮，我人工在 Simulink 界面里拖，**五分钟的事**。求解器的配置，我调一调参数，大概也能过。这件事的分工，从一开始就没摆对。

AI 适合做反复试错、机械检索的活。库名、参数名、端口名，这些零碎的东西，它一个一个查，不知疲倦。可它没有物理直觉，不知道一个电路该长什么样，不知道求解器为什么收敛不了。这些地方，人看一眼就知道问题在哪。

这次没搭成自动构建仿真的路。**从入门到放弃**，中间隔了四十四根线和一道代数环。前半段平整，后半段断在求解器前面。剩下的路，得人走完。

API 的余额花了一些，时间花了不少，换来的就是这份清单。后来的人照着这份清单走，能少踩几个坑。
